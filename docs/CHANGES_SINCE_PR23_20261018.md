# SoloScape: every change since PR #23

Report date: **18 October 2026**. This is a historical snapshot, not a replacement for [CURRENT_STATUS](CURRENT_STATUS.md).

## Scope and headline result

Baseline is merged [PR #23](https://github.com/kannibalk1w1/SoloScape/pull/23), commit `0836b5dfa6ebabf3cffe51a4d55868e62fe98fe1`. Native coverage ends at merged **PR #89**, `d6925aa7d9df894abf19c9e63d7f38e4e0f3fa21`. There are **66 subsequent merged PRs**, plus the separate **open draft WASM PR #27**. PR #22 is included because it merged *after* #23; PR numbers are not chronological. #23 itself is the baseline, not a new change in this report.

The native comparison contains **333 changed paths, 35,256 added lines and 91 removed lines**. These are Git textual statistics, including patch files, tests, evidence and documentation; they are not a measure of new gameplay. The tracked stacks grew from **53 to 56 client patches** and **22 to 52 server patches**. Many server patches add tests only. Current source exports cover 140 client and 105 server files.

The largest outcome is a more dependable native game: fixes for saves, inventory loss, item charges, familiar/NPC identity, dungeon generation/rewards and Slayer blocks. Controller corner movement and RT walking are added. A real earned Lumbridge progression slice and many bounded native contracts are validated. Packaging/update and backport experiments advanced substantially, but neither a production auto-updater nor imported later gameplay has shipped. WASM now has a connected original-model-to-framebuffer proof, still far short of a playable client.

The 2011 foundation, pre-EoC rules, server authority, tile collision and native Deck priority remain intact. The earlier UI overhaul, animated launcher braziers, font changes, quest projection and most controller panels predate #23 and are **not additions from this period**.

## What changed for play

### Movement, launcher and controller handling

- **Legal L-shaped running:** re-evaluate the second step from the tile reached by the first. The server still checks each step; blocked diagonals cannot cut corners. Disable switch retains previous behavior.
- **RT precision walking:** hold RT to walk at full stick tilt in verified direct mode; release to restore the run threshold. This is continuous one-tile-per-tick walking, not a one-step-per-press mode. LT still owns aim.
- **Launcher modal input:** deferred A activation avoids blocking its input timer; nested dialogs use owner ancestry; B restores parent focus. Late update replies do not reopen cancelled settings.
- **Check for updates:** explicit launcher action retrieves stable public GitHub release metadata/notes, including offline/no-release states. It does **not** download, install or switch a build.
- **Settings test ownership:** connected virtual-pad lifetime and explicit direct-mode coverage remove misleading harness failures. The old real-Deck one-tile save discrepancy remains unexplained; later passing runs are not a claimed fix.

There is no new tile cursor, queued waypoint system, attack-from-here modifier, safespot rule change or weakening of native attack auto-approach. Physical corner/RT/safespot acceptance remains necessary. [Movement details](CONTROLLER_CORNER_MOVEMENT.md).

### Dungeoneering, cooking, Summoning and Slayer

- Dungeon rotation now preserves both original coordinates. Old quarter-turn logic could collapse an entire room into a line, affecting boss/key-object scans.
- Dungeon next-floor timeout now begins after queued reward work, preventing long notice-reading from losing XP/tokens/floor credit.
- Cooking clears stale activity state when a queued fire or input disappears.
- Familiar late-hit Slayer credit stays with the exact original online player object, not whoever later occupies its index. Dismissal clears identity and avoids double removal.
- Deferred NPC allocation/removal now reserves pending indices and checks object ownership, preventing duplicate allocation, cancelled spawns, stale replacement removal and count/lookup corruption.
- Slayer paid blocks now persist in all five existing slots and actually exclude tasks. Existing unblock controls work; relevant reward panels refresh. Empty eligible lists show native dialogue without losing prior assignment/streak, while genuine missing-table errors remain visible.

These repair existing systems. No new Summoning roster, dungeon floors, Slayer superior mechanic, modern task system or balance overhaul was added.

### Death, loot and item conservation

- Failed whole-pile pickup transactions keep the original floor loot; stale references roll back tentative inventory additions.
- Older grave cleanup cannot clear newer grave state; markers are independently removed; Demolish no longer double-removes its NPC.
- Protected charged equipment preserves its stored charges; dropped charged equipment carries them into floor loot and back through Take.
- Identical nonstackable copies are independently counted for protection, including copies split between inventory and equipment.
- Grave phases progress in order, and expiry cancels the timer so scheduled cleanup runs.
- Gravestone purchase confirmation now enforces native quest availability server-side before charging.

**Open P1:** unrecovered graves/floor loot still disappear across a full world restart. This was positively reproduced in two cold JVMs. The agreed policy is to pause grave lifetime while closed, but production persistence is not implemented. Codec/checkpoint experiments below do not close it. [Plan and gates](GRAVE_PAUSE_PERSISTENCE_PLAN.md).

## Saves, profiles and recovery

The important shift is requiring evidence of the *current primary save*, rather than treating an orderly process exit or an older readable file as success.

- Failed-write/unfinished-save artifacts prevent a clean closure claim and after-clean backup.
- Native world shutdown confirms primary-save outcome for the exact owned session; missing/wrong confirmation leaves closure unverified. A forced primary+fallback failure with no error artifact proves why this is needed.
- Failed offline snapshots stay queued until primary success; fallback success alone does not lift retry/login protection.
- Queued save capture copies persisted list containers, preventing later gameplay edits from mutating an earlier IO snapshot.
- Malformed profile and session metadata are isolated without hiding healthy characters or signaling unverified processes.
- Backups verify primary character identity in addition to checksums. Corrupt compressed streams stay visible as invalid beside usable recovery options; failed restores preserve existing state.
- Optional `SOLOSCAPE_PROFILE_HOME`, `SOLOSCAPE_CACHE_HOME` and `SOLOSCAPE_LAUNCHER_HOME` separate durable state/input/art from replaceable code. Defaults are retained and no migration runs automatically. Shell entrypoints export the selectors correctly.
- Owned game environments remove late `_JAVA_OPTIONS` overrides that could redirect profile home/cache away from the selected paths.

Private co-op validation used two actual clients, separate accounts, visible movement and a full server restart. It proves a narrow compatibility boundary; there is no new hosting UI, guest lifecycle/loot policy or physically accepted co-op product.

### Backport Lab

The hard remaining work is consumer-safe permanent allocation, dependency/appearance conversion, affected-save compatibility/removal and provenance. **No real OSRS content or proprietary asset was imported into Git.** Superior-Slayer-style behavior remains a candidate; use native existing/recoloured assets first and preserve pre-EoC rules. ### GitHub updater and private prebuilt delivery

- **Staging lab (#53, hardened #89):** bounded original ZIP/manifest validation, frozen hash input and exclusive candidate publication; rejects existing destinations, malformed members/streams, FIFO archives and nonregular guards. Latest scope: 26 staging cases.
- **Source-free server closure (#61):** native server boots/stops from read-only jar/data with external cache/state, identifying a tested runtime allowlist.
- **Private prebuilt sessions (#65):** real New/Continue from immutable payload; first audio enumeration hang was retained as a failed run; qualified runs explicitly exclude audio.
- **Graphical preflight (#66):** actual launcher/backend works through a private manifest adapter without source Git/Gradle/compiler assumptions; production bootstrap remains unchanged.
- **Version ownership/recovery/rollback (#71):** second copied version cannot take over the first live world; original context can recover it; candidate progress survives returning to older code without restoring a backup. This covers the tested server42/45 pair, not arbitrary downgrade compatibility.
- **Stopped-world activation lab (#74):** stable shared world/child leases prevent exclusive pointer changes until stopped; marker/sealed-candidate checks and publication-cut controls pass; unsafe shared-lock mutation is caught. No candidate execution or production activation.
- **Runtime/notice inventory (#72):** 55 server and 24 client artifacts inventoried, with candidate notices/native libraries and three explicitly unattributed local client jars. This does not clear redistribution rights or notice completeness.

The launcher can discover updates; it cannot yet safely download/apply them in production. Package authority/authentication, real installer integration, health confirmation, multi-profile install ownership, compatibility and release licensing remain open. Private ready payloads include separately supplied assets/JDKs/state and must not be uploaded as public releases. [Delivery plan](GITHUB_UPDATES.md).

## WASM and Tauri: separate draft PR #27

Branch `kannibalk1w1/wasm-renderer-investigation`, reviewed head `3aff4ed5cdf1457e0ee34aea97fbe7298de7ab96`, is synchronized through native #89. It remains **open/draft and must not merge into native main**. Native-sync merges are maintenance, not extra WASM features.

| Step | Change / result | Limit |
| --- | --- | --- |
| Java boundary | Unchanged StickMath compiles/runs through TeaVM 0.16 WasmGC; AWT presenter rejects Rectangle/DirectColorModel/Applet closure | Pure logic portability, not AWT/Swing/RuneLite portability |
| Masked-edge kernel | Native bytecode, extracted JVM and browser agree at 765×503/1280×800; wrapper/clock/error controls hardened | Synthetic edges, not triangles or scenes |
| Flat triangles | Actual native flat fill/depth/blend paths match on original triangle/2,180-triangle mesh across runtimes | Bounded extracted closure; wireframe/platform paths excluded |

| Shaded/textured fills | Four non-flat native fill roots, original synthetic textures, matching colour/depth at both sizes; evidence tightened and three load-contaminated runs retained | Texture sourcing/material scene integration and meaningful full-game performance unresolved |
| Projection/face selection | Native transforms, bounded cameras/culling/flat dispatch checked against independent geometry and native outputs | No full native model constructor, scene/world or lighting pipeline |
| Near-plane clipping | Initial bounded proof extended to 28 rows, including general matrix/adapter inputs; actual extracted fill counters and corruption controls | Synthetic bounded cases; native exceptions can be swallowed, so positive observations matter |
| Old-format model decode | Five originally encoded models decode to independent expected arrays in native jar/JVM/WASM; malformed-output controls | Optional/new formats, animation/labels/material streams and arbitrary input safety unproven |
| Decoded model → frame | Three original tetrahedra × two cameras × two sizes = 12 cases/runtime; arrays/projection/selection/colour/depth match; canonical Canvas readback `a0bf99a6` | Adapter bypasses full model construction/lighting; original palette, not real cache appearance |
| Linux Tauri engine | Same unchanged decoded-face fixture passes all 12 cases/four corruptions in WebKitGTK 2.54.1; fresh isolated rerun 18 October | Host engine proof, **no Tauri executable**, actual Deck engine, lifecycle integration or speed comparison |

The decoded-face fixture is 107,301 raw WASM bytes (36,674 normalized gzip), plus 17,268 raw runtime-JS bytes. These tiny bounded module sizes do **not** predict a full game payload. Earlier research measured the supplied cache near 185 MiB; it is neither a distributable web bundle nor a full browser memory estimate.

Tauri remains a plausible packaging/native-integration option. Rust around a CPU rasterizer does not inherently make it faster. A fair performance decision needs one representative scene measured in native Java, Chromium and target WebKit, separating raster, RGBA conversion, presentation, memory and power. No such comparative game-scene benchmark exists.

The recommended route remains a browser-capable client experiment with the **existing Java server** if the graphics/platform path proves worthwhile. A local WASM server or protocol-free integrated runtime is deferred. AWT/Swing/RuneLite replacement, input/Gamepad API, networking/cache traffic, durable browser saves, audio, threads and scene dependencies remain major unproven work. No public browser asset delivery or WebGPU rewrite was approved.

## Documentation and workflow additions

- Generated current acceptance ledger separates implementation/automated validation from physical acceptance; immutable dated reports remain evidence. Its reviewed baseline can intentionally predate the latest docs-only/lab merge.
- Human playtest GitHub issue form captures commit/build, hardware/mode/input, activity, expected/actual behavior, reproduction, severity and evidence. P0: data loss/serious lifecycle; P1: progression/controller blocker; P2: recurring friction; P3: polish.
- Architecture/backport/WASM source research, cache/storage setup, content audits, roadmap updates and explicit current-build link keep future work tied to concrete gaps.
- Exact patch reproduction, frozen inputs/manifests, independent expected-state checks and deliberately failing controls were added throughout the experiments. A passing checker is not sufficient if it only accepts its own generated expectations.
- Claude was used for bounded targeted implementation/audits/reviews, including Haiku for Summoning/dungeon/ownership/save/update checks. Reviews are not human acceptance or substitutes for native execution; final evidence was independently checked.

## Outstanding work and recommended order

1. **Physical acceptance of the prepared native changes:** corners/RT, ranged and magic safe spots, dungeon entrances/keys/boss/rewards, Summoning panels/dismissal and Slayer blocks. The owner reports Lumbridge → Wizards Tower playable without blockers; that does not accept later host-only patches.
2. **Close the open unrecovered grave/floor-loot P1:** choose and prove live capture/claim/recovery/backup semantics under pause-while-closed before integrating a production writer. Preserve independent conservation controls.
3. **Finish one full earned solo dungeon and one earned Summoning journey**, then repair only reproduced shared blockers. Do not run every quest or expand the content roster merely to increase test counts.
4. **Deck lifecycle/performance campaign:** real Desktop/Gaming Mode input, audio, reconnect/focus, region frame tails, battery, suspend/resume and low-battery exit. Current input-gap resets are not a simulation pause.
5. **Production updater integration**, after packaging/rights/authority/stopped-world/rollback gates. Keep lab staging and private payloads distinct from public distribution.
6. **Backport appearance/dependency and safe allocation proof**, then one tiny native later-content experiment. Keep WASM as a separate measured research track; next investigate a bounded constructor/lighting seam or representative scene, not a full port.
